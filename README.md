# AI Assistant Interface — Web Reactor Test Assignment

Высокопроизводительное FullStack-приложение (ИИ-ассистент), разработанное в качестве тестового задания для компании **Web Reactor**. Проект представляет собой полноценный чат-бот с поддержкой истории переписки, симуляцией эффекта печати ИИ в реальном времени и встроенной системой голосового ввода (Speech-to-Text).

## 🚀 Живая демо-ссылка (Production)
* **Frontend (Static Site):** [https://webreactor-ai-chat.onrender.com](https://webreactor-ai-chat.onrender.com)
* **Backend (API Service):** [https://webreactor-ai-api.onrender.com](https://webreactor-ai-api.onrender.com)

> **Примечание по бесплатному хостингу:** Бэкенд развернут на бесплатном тарифе Render и «засыпает» после 15 минут бездействия. При отправке первого сообщения серверу может потребоваться около 30–40 секунд на холодный запуск. Последующие запросы обрабатываются мгновенно.

## 🛠 Технологический стек

### Frontend
* **React 18** (Vite) — быстрая сборка и модульная структура Single Page Application.
* **Tailwind CSS v4** — использование новейшего JIT-движка и переменных темы на уровне CSS.
* **Web Speech API** (`webkitSpeechRecognition`) — нативное клиентское распознавание речи «на лету» без нагрузки на бэкенд и отправки тяжелых аудиофайлов.
* **Кастомные хуки React** — полная изоляция бизнес-логики (API, медиа-потоки) от UI-рендеринга (SRP).

### Backend
* **.NET 10 (ASP.NET Core Minimal APIs)** — выбран для демонстрации навыков проектирования строго типизированной, отказоустойчивой и масштабируемой серверной архитектуры.
* **Паттерн Options** — строго типизированная валидация конфигурации внешних ИИ-сервисов.
* **HttpClientFactory** — оптимальное управление пулом сокетов для предотвращения Socket Exhaustion при частых запросах к LLM.

### DevOps & Инфраструктура
* **Docker & Multi-stage Сборка** — оптимизация веса итоговых образов (разделение SDK и Runtime слоев).
* **Docker Compose** — оркестрация мультиконтейнерного окружения для локальной разработки.
* **Nginx** — настроен внутри контейнера фронтенда в качестве **Reverse Proxy** для проброса API-запросов во внутреннюю сеть Docker, что полностью решает проблему с CORS и маршрутизацией.

## 🔑 Настройка Groq API Ключа

Для работы нейросети используется **Groq API** (полностью совместимый с OpenAI формат эндпоинтов). 

### 1. Получение ключа
1. Перейдите на консоль разработчика [Groq Cloud Console](https://console.groq.com/).
2. Авторизуйтесь и перейдите в раздел **API Keys**.
3. Нажмите **Create API Key**, скопируйте его (он начинается на `gsk_...`).

### 2. Конфигурация для локального запуска (Docker Compose / dotnet run)
Откройте файл `WebReactor.Backend/WebReactor.Backend/appsettings.json` и вставьте ваш ключ в поле `ApiKey`:

```json
"AiSettings": {
  "ApiKey": "gsk_ваш_реальный_ключ_здесь",
  "ApiUrl": "[https://api.groq.com/openai/v1/chat/completions](https://api.groq.com/openai/v1/chat/completions)",
  "Model": "llama-3.3-70b-versatile"
}
